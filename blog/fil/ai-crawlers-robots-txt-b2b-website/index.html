GEO at AI search

Bina-block ba ng Website Mo ang ChatGPT? robots.txt para sa AI Crawler sa mga B2B Site

Bago ang content, i-check ang access. Maraming export website ang hindi sinasadyang nagba-block ng AI search crawler sa pamamagitan ng robots.txt, CDN o security plugin. Ganito makikilala ang search bot sa training bot at kung ano ang dapat payagan.

Ang tanong sa likod ng artikulong ito

Bina-block ng IT team namin ang "AI bots" sa website noong nakaraang taon. Iyon ba ang dahilan kung bakit hindi kailanman ipinapakita ng ChatGPT ang factory namin, at ano ang dapat naming payagan?

Maikling sagotPosibleng-posible. Magkahiwalay na bot ang pinapatakbo ng mga AI company para sa search at para sa model training. Sabi ng OpenAI, hindi ipinapakita sa ChatGPT search answers ang mga site na nag-opt out sa OAI-SearchBot, habang training lang ang sakop ng GPTBot. Payagan ang mga search crawler (OAI-SearchBot, PerplexityBot, Googlebot, Bingbot), magpasya nang hiwalay tungkol sa mga training bot gaya ng GPTBot at Google-Extended, at i-check na hindi sila bina-block ng CDN o firewall mo anuman ang nasa robots.txt.

Mahahalagang punto

  • Ipinapakita ng OAI-SearchBot ng OpenAI ang mga site sa ChatGPT search; para sa training ang GPTBot. Magkahiwalay ang settings, kaya puwede mong payagan ang search at tanggihan ang training.
  • Sabi ng OpenAI, puwedeng umabot nang mga 24 oras bago maapektuhan ng pagbabago sa robots.txt ang ChatGPT search.
  • Ipinapakita at nili-link ng PerplexityBot ang mga site sa resulta ng Perplexity at, ayon sa Perplexity, hindi ito ginagamit para mag-train ng foundation model.
  • Kinokontrol ng Google-Extended ang paggamit ng content mo para sa Gemini training at grounding; sabi ng Google, hindi nito naaapektuhan ang pagkakasama o ranking sa Google Search.
  • Kayang i-block ng firewall at CDN ang mga crawler kahit pinapayagan sila ng robots.txt; dahil dito, naglalathala ang Perplexity ng IP range at WAF instructions.

Nakakagulat kung gaano karaming export website ang hindi nakikita sa AI search dahil sa isang nakakabagot na dahilan: hindi makapasok ang mga crawler. Sa nakalipas na dalawang taon, may nagdagdag ng "block AI bots" na rule, nag-on ng bot protection ng CDN o nag-install ng security plugin. Gumagana pa rin ang site para sa mga tao, kaya walang nakakapansin. Pagkatapos, ilang buwang isinusulat muli ng team ang content na hindi kailanman pinayagang basahin ng mga AI search engine.

Ang gabay na ito ay 30-minutong technical check para sa mga factory at B2B website. Hindi ka nito gagawing visible nang mag-isa, pero kung sira ang access, walang ibang gagawin mo ang mabibilang.

Aling mga AI crawler ang para sa search, at alin ang para sa training?

Ang pangunahing ideya: hinihiwalay ng mga AI company ang bot na naghahanap ng mga page na ipapakita sa sagot mula sa bot na nangongolekta ng content para sa model training. Puwede kang gumawa ng magkaibang pagpili para sa bawat isa.

Iba ang paggana ng sariling AI features ng Google sa Search. Sabi ng gabay ng Google, nakapaloob ang AI sa Search, kaya ang robots.txt rules para sa Googlebot ang kontrol sa kung paano kina-crawl ang isang site para sa Search, kabilang ang AI Overviews at AI Mode. Ang pag-block sa Googlebot para "mag-opt out sa AI" ay mag-aalis din sa iyo sa ordinaryong search results.

Ano ang dapat nakasaad sa robots.txt ng isang factory website?

Para sa karamihan ng export manufacturer, ang layunin ay mahanap, kaya payagan ang mga search crawler. Desisyong pang-negosyo kung papayagan ang mga training crawler; hindi ka maaalis sa AI search kapag tinanggihan mo sila. Ganito ang hitsura ng simpleng panimula:

Ilayo sa mga crawler ang mga pribadong bahagi, gaya ng dealer portal o price list, gamit ang login protection, hindi lang robots.txt. Tahasang sinasabi ng robots.txt documentation ng Google na hindi mekanismo ang robots.txt para hindi mapasama ang isang page sa Google; gumamit ng noindex o password protection para diyan.

Bakit kayang i-block ng firewall ang AI crawler kahit pinapayagan sila ng robots.txt?

Pakiusap ang robots.txt; tarangkahan ang CDN, firewall o security plugin mo. Maraming bot-protection feature ang humahamon o nagba-block sa mga hindi kilalang crawler bago pa nila mabasa ang robots.txt. Kasama sa basics ng Google para sa AI features ang "ensuring that crawling is allowed in robots.txt, and by any CDN or hosting infrastructure". Mas malayo pa ang Perplexity at naglalathala ito ng mga listahan ng IP address at hakbang-hakbang na web application firewall rules para mapayagan ng mga may-ari ng site ang mga bot nito. Naglalathala rin ang OpenAI ng IP range para sa mga crawler nito.

Tanungin ang humahawak ng hosting mo ng tatlong tanong: naka-on ba ang bot protection, may allow list ba ito, at nasa listahan ba ang mga search crawler sa itaas? Pagkatapos, i-check ang server logs mo para sa mga user agent sa table. Kung lumalabas sila at nakakatanggap ng error, o hindi kailanman lumalabas, nahanap mo na ang problema.

Paano i-check ang access sa loob ng 30 minuto?

  1. Buksan ang yoursite.com/robots.txt. Hanapin ang Disallow: / sa ilalim ng User-agent: * o sa ilalim ng anumang AI user agent.
  2. I-check ang CDN o firewall para sa bot protection, country blocking o mga "AI scraper" toggle.
  3. Hanapin sa server logs mo ang OAI-SearchBot, PerplexityBot at Googlebot, at ang mga status code na natatanggap nila.
  4. Kumpirmahin ang indexing sa Google Search Console para sa mga pangunahing product at capability page mo.
  5. Mag-test muli sa ChatGPT pagkalipas ng isang araw. Sabi ng OpenAI, puwedeng umabot nang mga 24 oras bago lumabas sa search ang pagbabago sa robots.txt.
  6. Isulat ang policy, para hindi ito mabura ng susunod na security update.

Ibig bang sabihin ng pagpayag sa crawler ay irerekomenda ka ng AI?

Hindi. Ginagawa kang eligible ng access; hindi ka nito ginagawang napili. Kapag kaya nang basahin ng mga crawler ang site mo, ang susunod na tanong ay kung sinasagot ng mga page mo ang tanong ng mga buyer gamit ang tiyak na facts, at kung consistent ang impormasyon ng kumpanya mo sa buong web. Pero access ang nauuna. Ito ang pinakamurang ayos sa GEO at ang pinakamadalas makaligtaan.

Insight
Hindi ka masisipi ng engine na pinagsarhan mo.

Sabi ng bottleneck thinking mula sa operations research, itinatakda ng pinakamakitid na bahagi ang output ng isang system. Para sa AI visibility, kadalasang crawler access ang bahaging iyon: walang dami ng content work ang makakapagpataas ng resulta hangga't hindi bukas ang tarangkahan.

FAQ

Kung iba-block namin ang GPTBot, titigil ba ang ChatGPT sa pagpapakita ng site namin?

Hindi, ayon sa OpenAI. Kinokontrol ng GPTBot kung puwedeng gamitin ang content para sa model training; kinokontrol ng OAI-SearchBot ang paglabas sa ChatGPT search. Magkahiwalay ang dalawang setting, kaya puwede mong i-disallow ang GPTBot at payagan pa rin ang OAI-SearchBot.

Aalisin ba kami sa AI Overviews kapag bina-block ang Google-Extended?

Hindi. Sabi ng Google, hindi naaapektuhan ng Google-Extended ang pagkakasama sa Google Search, at bahagi ng Search ang AI Overviews at AI Mode, na kinokontrol sa pamamagitan ng Googlebot. Para limitahan ang lumalabas sa snippets at AI features, tinuturo ng Google ang nosnippet, data-nosnippet, max-snippet o noindex.

Kailangan ba namin ng llms.txt file para mahanap ng AI?

Sabi ng Google, hindi mo kailangan ng bagong machine-readable file o AI text file para lumabas sa AI features nito. May mga site na naglalathala ng llms.txt bilang dagdag na buod para sa mga AI tool, pero hindi ito kapalit ng mga page na kayang i-crawl.

Gaano katagal pagkatapos ayusin ang robots.txt bago kami makakita ng pagbabago?

Sabi ng OpenAI, puwedeng umabot nang mga 24 oras bago umangkop ang mga system nito sa update ng robots.txt para sa search. Nakasalalay pa rin sa content mo kung masisipi ka, kaya sukatin sa mga susunod na linggo sa halip na kinabukasan.
